## چه وقت استفاده شود

- کاربر می‌خواهد یک prompt فارسی از صفر بنویسد.
- یک prompt فارسی جواب بی‌ثبات یا سطحی می‌دهد و باید بازنویسی شود.
- خروجی مدل فرمت مشخصی ندارد (باید JSON، جدول، فهرست باشد).

## روش

یک prompt خوب شش بخش دارد. همه لازم نیستند، ولی به همین ترتیب بیایند:

۱. **نقش** — «تو یک ویراستار فارسی هستی که…». نقش، لحن و سطح تخصص خروجی را تعیین می‌کند.

۲. **وظیفه** — یک جملهٔ فرمانی و مشخص. فعلِ دقیق: «خلاصه کن»، «دسته‌بندی کن»، «بازنویسی کن» — نه «کمک کن».

۳. **زمینه** — متن ورودی، داده، یا محدودیت‌های موقعیت. با جداکنندهٔ واضح از دستور جدا کن (`---` یا تگ `[متن]…[/متن]`).

۴. **فرمت خروجی** — دقیق بگو: «فقط JSON با کلیدهای `title` و `tags`»، «جدول سه‌ستونه»، «حداکثر ۵۰ کلمه». اگر نگویی، مدل هر بار فرمت عوض می‌کند.

۵. **مثال** — یک یا دو نمونهٔ ورودی→خروجی. برای کارهای فرمت‌محور، مثال از هر توضیحی مؤثرتر است.

۶. **محدودیت‌ها** — «اگر اطلاعات کافی نبود بگو نمی‌دانم»، «چیزی از خودت اضافه نکن»، «اصطلاح فنی را ترجمه نکن».

## مثال

```
تو یک دسته‌بند محتوای فارسی هستی.

وظیفه: متن زیر را در یکی از این دسته‌ها بگذار: خبر، آموزش، تحلیل، معرفی محصول.

[متن]
{{article}}
[/متن]

خروجی: فقط JSON به شکل {"category": "...", "confidence": 0.0}
اگر متن به هیچ دسته‌ای نمی‌خورد category را "نامشخص" بگذار.
```

## خطاهای رایج

- **دستور و متن قاطی** → مدل نمی‌داند کجا دستور تمام می‌شود. همیشه جداکننده.
- **وظیفهٔ مبهم** («این را بهتر کن») → خروجی دلبخواه. فعل + معیار مشخص.
- **نگفتن فرمت** → خروجی هر بار متفاوت، برای پردازش برنامه‌ای بی‌فایده.
- **نیم‌فاصله و یکدستی** → اگر خروجی باید نیم‌فاصلهٔ درست داشته باشد، صریح بخواه؛ مدل‌ها اغلب فاصلهٔ کامل می‌گذارند.
- **ابهام واژگانی فارسی** («شیر»، «کلید») → اگر در دامنهٔ کارت مهم است، در محدودیت‌ها روشن کن.
- **اعداد** → اگر خروجی عددی برای محاسبه است، بخواه ارقام لاتین باشد نه فارسی.

## بررسی نتیجه

- prompt را سه بار با همان ورودی اجرا کن؛ خروجی‌ها باید هم‌فرمت و هم‌محتوا باشند.
- یک ورودی لبه‌ای بده (خیلی کوتاه، بی‌ربط)؛ آیا مدل طبق محدودیت رفتار می‌کند؟
- خروجی را به کسی نشان بده که prompt را ندیده؛ آیا می‌فهمد چه خواسته شده بود؟
