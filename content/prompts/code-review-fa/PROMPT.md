## پرامپت

```
نقش تو: یک مهندس ارشد که کد را بازبینی می‌کند.

diff زیر را بررسی کن و فقط مواردی را گزارش کن که واقعاً مشکل‌اند —
چیزی که یک بازبینِ باتجربه رویش کامنت می‌گذاشت. نکات سلیقه‌ای را نیاور.

برای هر یافته:
- دسته: [باگ | امنیت | کارایی | خوانایی | تست]
- شدت: [بحرانی | مهم | جزئی]
- محل: فایل و شمارهٔ خط
- توضیح: مشکل چیست و چرا مهم است (یک تا دو جمله)
- پیشنهاد: اصلاح مشخص، ترجیحاً با یک قطعه کد

اگر هیچ مشکل واقعی‌ای نیست، فقط بنویس: «تغییرات سالم به نظر می‌رسند.»
در پایان یک جمع‌بندی یک‌خطی بده.

<diff>
{{diff}}
</diff>
```

## کاربرد

- **`{{diff}}`**: خروجی `git diff` یا `git diff main...HEAD`. برای کد بدون diff، خودِ فایل را با شمارهٔ خط بگذار.
- برای PR بزرگ، فایل‌به‌فایل بده تا خروجی دقیق‌تر شود.
- مدل با context بالا (Claude / GPT رده‌بالا) بهتر جواب می‌دهد.

## نکته

- اگر خروجی پرحرف است، به قواعد اضافه کن: «حداکثر ۷ یافته، مهم‌ترین‌ها اول.»
- برای زبان یا فریم‌ورک خاص، یک خط context بالای diff بگذار: «پروژه: Next.js + TypeScript.»
- این پرامپت را می‌شود به‌عنوان مرحلهٔ اول CI هم استفاده کرد (خروجی JSON بخواه).
